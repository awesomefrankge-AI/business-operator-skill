# Frank 的业务操盘方法论

> 一套把业务问题转成模型、目标、验证计划和团队动作的实践框架，面向经营者、业务负责人和增长顾问。

## 方法概要

Frank 的方法从业务事实出发：先看客户价值和经营阶段，再画增长与交付模型，找到关键变量，设定目标并组织验证，最后把有效做法沉淀为团队流程。

| 业务问题 | 方法输出 |
|---|---|
| 不清楚业务如何增长 | 全局/局部业务模型、收入公式、关键增长变量 |
| 老板的问题模糊或沟通不同频 | 问题分层、决策所需证据、可选方案与建议 |
| 目标大而空或执行脱节 | 目标拆解、必要前提、分支抓手、责任人与节奏 |
| 新项目验证混乱 | 假设清单、定量与变量、最小验证计划、证实/证伪标准 |
| 团队拿不到结果 | 目标到人、周节奏、复盘、1on1、IDP、EDAC 培养计划 |

**核心原则**：把业务经营模型化；用可验证的变量而非任务清单管理结果；先验证用户价值，再投入资源规模化。

## 安装

```bash
git clone https://github.com/awesomefrankge-AI/business-operator-skill.git ~/.agents/skills/business-operator
```

Codex 启动后会识别 `SKILL.md`。

## 使用

直接描述业务问题即可，或显式输入 `/business-operator`：

```text
帮我梳理这家公司的业务模型和收入公式
老板要我半年做到 GMV 增长 50%，请拆目标、约束和执行节奏
帮我为 AI 获客方向设计一个变量不超过两个的验证计划
请把方案整理成老板能决策的一页纸
```

信息不足时，先询问公司阶段、目标、用户和当前数据；缺失数据明确标注为假设，不编造事实。

## 内容结构

- `SKILL.md`：触发路由、工作流、质量原则与适用边界
- `references/00-06`：经营画像、高层沟通、业务模型、模型库、规划、探索、团队管理
- `references/07-ai-era.md`：AI 对成本结构、增长路径、组织与验证方式的影响
- `templates/`：业务模型、目标拆解、探索假设、汇报、复盘、1on1、IDP 等可填写模板

## AI 时代的扩展

在传统业务模型上增加 AI 能力评估：哪些环节能提升吞吐、降低边际成本或改善交付稳定性；哪些数据、信任、分发和独家供给仍稀缺；并将 AI 能力本身作为待验证变量，避免与用户需求同时混测。

## 使用边界

- 这是 Frank 持续整理和迭代的个人工作方法，不是通用真理，也不声称每个框架或案例均为原创。
- 历史案例仅用于说明推理过程；涉及当前市场、法规、产品和财务数据时，需独立核验。
- 不适合只由关系资源或行政指令决定结果的场景。
- 投资、法律、医疗等高风险判断不能只依赖本框架。
