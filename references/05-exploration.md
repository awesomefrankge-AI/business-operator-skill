# 探索型项目的破局

来源：课程第五章。用于：用户负责 0→1 项目、新业务、新渠道、新产品、验证一个想法；或者复盘一个失败的探索项目为什么失败。

**核心纪律：定量足够多足够稳定，才有机会围绕少数变量完成验证。N 多变量叠加又无定量的探索项目注定失败。证实和证伪都有价值，稀里糊涂的失败毫无价值。**

---

## 1. 什么是探索

对项目"最终长成什么样"+"怎么一步步长成"有想象，据此规划行动路径，逐一解决障碍。

商业探索最终要描绘一个**完整商业故事**，三层：
| 编号 | 层 | 内容 | 对应 |
|---|---|---|---|
| ① | 商业价值构想 | 市场赛道 / 机会 / 商业模式 / 核心产品 → 能值多少钱 | 战略层 |
| ② | 产品用户价值和业务逻辑构想 | 用户价值如何稳定产生 / 交付供给保障 / 模块关系 | ≈ 全局业务模型 |
| ③ | 执行运作方式构想 | 新渠道 / 新玩法 / 新转化产品 / 交付 / 供应链怎么做 | ≈ 局部业务模型 |

探索项目成功至少 = ② 稳定 + ③ 成型。

**开篇案例：两个中国版 Product Hunt（2016）**
- 36 氪 NEXT：认为站内有流量，定期更新案例 + 官网导流 + 版本更新，以产品功能体验驱动 → UGC 氛围从未形成 → 关停。
- 三节课酷产品：先做业务逻辑假设（官方批量更新案例 → 定向邀请专业 PM / 运营解读形成讨论 → 卷入大咖和产品 maker 引发深度讨论）→ 三个关键排优先级（围绕少量案例生成专业讨论 最高 → 引入大咖 次高 → 案例批量更新 靠后）→ 聚焦关键①：初始内容填充 + 种子用户定向运营 → **MVP：不开发工具，几十到一两百种子用户建邮件群组，每周更新 7-10 个案例，机制"发布自己观点后才能看别人的"，种子用户人肉维系** → 2 个月跑通，势头好 → 被 App Store 封杀。两者 ①② 相同，差在 ③。

负责探索项目的前提：中大型公司要有公司战略和商业价值判断的全局认知；必须有清晰的产品价值和业务逻辑假设；执行运作方式的构想要成熟。

全过程：从商业思考出发在三层提明确价值假设 → 沿假设快速行动 → 证实（放大价值完善模型）/ 证伪（回头重审假设）。

## 2. 基本工作逻辑四步

### 2.1 形成业务模型层面的价值假设
- 回到 `03-model-library.md` 的分类框架找借鉴。建议：对自己直接负责的模块，行业内常见相关模型要有清晰认知。
- 形式："我有 A 问题，假设 B 模型 / C 模型能解决"。怎么形成 B 是下一步。
- 案例·知识付费平台（话题直播 + 系列课，平台抽成）用户无留存无复购，靠一场场直播导流很累 → 复购属单体价值放大 → 假设 A：系列课后搭学习交流社区拉长留存周期再推荐其他课；假设 B：系列课间建关联形成用户成长体系 / 学习路径推荐复购。

### 2.2 梳理所有价值假设点，找权重更高的关键假设
新业务链条两类问题：①价值会不会被用户认可（有没有复购动机、课程关联性是否存在）②价值如何被创造（引导路径 / 机制 / 触达 / 激励 / 运营套路）。

**优先级铁律**：先解决"用户会不会买 / 有没有动机用"，再解决效率、供给、交付；供给交付中优先解决影响用户真实使用付费或交付基本前提的问题（滴滴拼车先控接单后等待时长，司机批量管理靠后）。

案例·操盘手课本身：
- 面前 N 多问题（5000+ 单价 / 能否培养出操盘手 / 助教怎么找 / 内容谁讲 / 难点多 / 服务交付方式）。
- 先解决价值认可：把自己当典型用户极致想象"做成什么样看到就想买" → 结果价值（优秀学员认证推荐一线公司主管岗，接受推荐拿不到 offer 退 50%；带真实业务问题学习，每章作业围绕真实业务）+ 过程价值（按行业分小组研讨行业业务模型；助教须一线公司团队管理 / 重要项目负责人，部分 VP 总监）。
- 2019 底活动现场 300 人 + 线上共四五百人公布内测 4000 元 → **15 分钟 120 名额抢光 = MVP 验证**，价值认可无需怀疑 → 之后所有问题变成"怎么达到承诺"。
- 价值如何创造：交付上"学习效果达成重于一切" → 假设：解决底层三件事（商业思维 / 业务模型 / 复杂问题拆解）上层问题自然有解 → 业务模型梳理重于一切 → 内测班聚焦一切资源验证用户能否理解习得业务模型，其他（内容生产 / 教学服务 / 班主任配合冲突）先人工个性化解决，后期再规范化 SOP → 验证成功才放大公测正式班。

### 2.3 按顺序验证直至证实 / 证伪：定量 vs 变量
方法：有链条和模型 → 拉出关键影响要素 → 各要素中稳定找到**定量**（已验证 / 已被用户认可 / 当前已是 yes）→ 确定**变量**且不能太多 → 反复测试。宏观层和微观业务流程层都适用。

- **正例·酷产品**：商业价值构想 = 定量（国外跑通，除非想做 10 倍）；用户价值和业务逻辑 = 定量（已发生）；执行运作 = 变量 → 三个问题砍掉两个只留"定向邀请 PM 产生专业解读碰撞" → 工具用邮件群组 = 定量、初始内容每周 7-10 案例 = 定量 → 变量只剩"怎么引导持续交流养成互动习惯"+"种子用户情感激励运营"。
- **反例·小 H（知识付费平台用户运营）**：原假设 = 用户分销把忠实用户发展为新渠道（只需验证有没有动机分销 + 有没有能力带订单）→ 产品总监的测评社区针对同批用户 → 老板合并 → 妥协方案：忠实用户写作群每周每人写 1 篇课程测评发社区 + 附分销二维码分成 → 2 个月群活跃但收入贡献 <1%，100 多篇内容优质少 → 关停。变量叠加（能否写出优质内容 / 有没有人看 / 看了能否转化 / 转化工具链路 / 社区流量怎么养）无定量 → 无法归因（人选不对？引导不到位？内容没分发？）。

### 2.4 增加资源投入放大模型
闭环验证后投资源让交付过程和部门衔接标准化、高效。

## 3. 三类常见探索型项目（三层假设的关系不同，方法相同）

| 类型 | 定量 | 思考顺序 | 案例 |
|---|---|---|---|
| **从 0 起步做独立项目** | 无 | 先基于 ② 产生用户价值假设 → 推演 ③ 形成计划 → ②③ 反复验证校正 → ② 稳定成定量 → 再基于 ② 思考 ① | 三节课 2015-2017 只想"线上课能否真实提升能力"，2017 产品生产交付稳定后才想商业价值和模式。绝大多数创业公司如此 |
| **商业角度先发现结构性机会，必须快速趟出通路** | ① = 定量（哪个赛道存在结构性机会、能孕育多大公司、时间窗口多长） | 基于 ① 形成 N 多 ②③ 假想（窗口半年 vs 一年决定假想数量）→ 多线并进快速趟路找到一种可依赖打法 → 放大 | 360 打百度（搜索格局老二必现拿 10%+ 份额，窗口半年到一年，5 条产品线同时跑）；腾讯微博两年；O2O 大战 |
| **基于现有业务体系解决一个问题（老板命题作文）** | ①② 中现有全局模型 = 定量；老板的命题本身 = 定量（不用怀疑用户会不会复购，只需证实 / 证伪） | 清晰理解全局模型，搞清我要解决链条哪段、哪些模块与我对接、input / output → 形成 ③ 局部业务模型假设开启探索 | 见下文文创电商 |

**亲历案例·大厂 A 2014 群组社交 APP**（第二类，刻骨铭心）：应对微信抢流量，投入不封顶。一线视角 = 按社区规律慢养（建几百个主题群，最活跃是多肉群和成语接龙群 → 聚焦少量功能做扎实）；老板 = 要快要多，驱动探索直播 / 明星付费社区 / KOL 课程工具 / 财经付费专栏；一线不理解，节奏混乱 → 一两千万用户后留存差 → 失败。事后反思：这是结构性机会 + 明确时间窗口（2014 一年，移动社交会出 3-4 款几千万上亿产品），老板唯一命题 = **一年内找到一套打法成为某细分战场头部**；老板在复用一个基本打法模型：绑定 KOL / 明星 + 快速投资源 + 抛话题 → 找到能规模化驱动增长的打法，在哪个方向找不重要；按一线逻辑两年做出两三百万用户社区毫无意义。**高层锁定结构性机会时，所有工作以它为定量展开，不纠结一线执行符不符合规律；半年多线快速出击拿结论，出来就放大，出不来就认了。**

**文创电商案例**（第三类）：三条增长线（线下门店 / 淘宝 + 店铺 CRM 复购 / 其他线上渠道投放分销）→ 首购用户送权益导公众号内容留存 → 小程序二次转化。学员负责微信流量池系统化复购（与淘宝 CRM 完全不互通）→ input = 公众号稳定粉丝沉淀 + 小程序稳定首次转化，若不稳定要先往前解决 → 业务模型假设：用户成长体系 或 定期上新 → 关键要素（复购价值成立否 / 典型场景 / 动机 / 触达手段 / 运营工具）→ 先验证动机和价值：**拉几百人用户群，结合热点基于文创 IP 上新品，用户下单预定够 50 个再生产** → 成立后再做触达机制工具场景。另一逻辑：把行业跑通的玩法（盲盒）当定量，产品适配性为变量直接套上跑。

产品经理做业务系统（CRM / 效率系统）同理：先梳理全局业务逻辑在内部形成共识（三节课：内容素材 → 内容单元 → 课程类型 → 开班计划 → 可售卖课程 → 前端上线 + 营销玩法 + 用户权益 → 售卖 → 版本管理 / 分班 / 个性化内容 → 班级内容 / 学员工作 / 班级群；系统 = 内容管理 / 班期管理 / 营销管理 / 教学运营管理）→ 明确我的系统在哪个环节服务谁、input / output。不看全局直接做几版方案反复对不上，效率极低。

## 4. 三类典型障碍

| 障碍 | 表现 | 应对 |
|---|---|---|
| 越往上靠近整体定位越开放、变量越多 | 成型产品探索抖音新渠道 = 有定量；独立探索一年营收 5000 万新产品 = 全是变量 | 先在稳定业务中做好局部探索，或稳定验证小型产品用户价值，再参与更复杂综合项目；不具备能力可以认怂，告诉老板不适合当前阶段的我 |
| 完全没经验、找不到模型指导 | 2015 负责滴滴顺风车，行业无成熟参照 | 先做业务逻辑基本假设（供需撮合匹配，服务 + 可能社交属性；需供给侧运营 / 交易撮合 / 司乘保障品控能力）→ 按 03 方法：检索相似行业（出行 / 电商平台 / 服务业）的相似模块 → 未解决问题（众包管理 / 线下社交关系缔结）再找同类问题解决方案（猪八戒威客供给端管理；线下交友活动关系缔结手段）。前提：对业务和用户深刻理解 + 熟知行业常见同类模型 + 善于快速学习 |
| 项目复杂、验证不扎实，越做变量越多、结论少，稀里糊涂失败 | 学习社区：打标签 → 个性化推荐 → 持续学习 → 留存 → 付费；第一环就撞上标签怎么打 / 内容稳定供给 / 内容组织 / 推了不爱看，四个人各管一线全不确定 | a. 不要一开始多层假设嵌套，把要验证的变量限制在小范围（本质只验证"给用户针对性内容用户会不会持续看" → 人肉给 100 个用户推一批内容，不看就问原因；标签和内容组织是实现手段后置）。b. 长周期复杂项目每周每条线都要取得关键进展和结论，只允许最多 1-2 个问题周期长，其余支线不断赢得定量而非制造变量 |

提醒：80%+ 探索项目注定失败，但要**明明白白地失败**（基于明确逻辑假设知道哪想错了）。拥有某项关键破局能力（如文案销售转化超强）的人探索对应类型项目胜率高。
